# AGENTS.md — zerno-app

## Обязательные правила

- `PROJECT_RULES.md` — обязательный источник инженерных правил. Перед изменениями изучай соответствующий раздел.
- Не делай выводы об устройстве проекта из общих знаний: проверяй актуальные документы, код, тесты и ADR.
- Исторические сведения не выдавай за текущее состояние. Непроверенные факты обозначай явно.

## Где смотреть

- `PROJECT_RULES.md` — обязательные инженерные правила.
- `docs/read-if-u-ai.md` — архитектура, стек и инфраструктурный контекст.
- `docs/module-map.md` — границы модулей, импорты и DOM ownership.
- `docs/css-architecture.md` — владельцы CSS, логические слои и cascade.
- `docs/frontend-todo.md` — актуальные задачи и UX-roadmap.
- `docs/api.md` — индекс API-маршрутов, методов и guard.
- `docs/openapi.yaml` — OpenAPI; сверять с серверными маршрутами и тестами.
- `docs/documentation-audit-2026-11-07.md` — последний аудит документации.

## Что устарело — не цитировать

- `docs7/**` — retired-зеркало; единственный поддерживаемый источник документации — `docs/`.
- `perf-report.md` — устаревший снимок, не актуальные показатели производительности.
- `docs/documentation-audit-2026-11-05.md` — заменён аудитом от 2026-11-07.
- Старые описания CSS с тремя слоями, «Слоем 0» или `theme-v2.css` не описывают текущую архитектуру.

В `PROJECT_RULES.md` §2 актуальна четырёхслойная модель CSS: 2a/2b — подслои слоя 2, а не отдельные верхнеуровневые слои.

## Обязательное правило ответа

Перед ответом на вопрос про архитектуру, CSS, DOM-владельцев, API или UX — сначала открой соответствующий файл из раздела «Где смотреть», затем отвечай. Не отвечай из общих знаний. При необходимости сверь документацию с текущей реализацией и тестами.
