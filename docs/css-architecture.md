# CSS-архитектура «…и кофе × Пятница»

**Статус:** нормативная карта логических владельцев CSS. Последнее обновление: 2026-11-15.
**Главный принцип:** логические слои ответственности не равны порядку подключения файлов или результату cascade.

## 1. Логические слои

### Слой 1 — базовый UI: `public/app/ui/theme/*.css`
Общие нейтральные стили, базовая геометрия, компоненты и общие состояния. Брендовые значения должны поступать из токенов. Не расширять селекторы бренда в базовом слое без отдельного архитектурного решения.

### Слой 2a — данные брендов: `public/app/ui/brand-tokens.css`
Только custom properties брендов. Не размещать здесь компонентную разметку, layout или состояния.

### Слой 2b — layout и брендовая синхронизация: `public/app/core/views.js`
Динамически подключаемые layout/media правила и брендовые поведенческие переопределения. Новые правила должны иметь обоснованный ownership, scope и responsive acceptance. Не дублировать здесь базовую геометрию без необходимости, но и не применять абсолютный запрет на layout: исключения принадлежат этому слою и должны быть явно объяснены.

### Слой 3 — локальные стили компонентов
Стили, создаваемые/подключаемые модулем-владельцем поведения (например, cart, delivery, chat). Их scope не должен захватывать чужие компоненты. Цвета используют токены.

### Слой 4 — critical CSS: `public/index.html`
Минимальная страховка первого кадра: фон, резервирование критической геометрии, ранние состояния splash/header и предотвращение FOUC/CLS. Полное состояние или полноценный стиль компонента здесь не дублируется.

## 2. Порядок подключения и каскад

- Логические слои выше описывают ownership, а не математический приоритет каскада.
- Файлы theme подключаются отдельными stylesheet links; точный список, порядок и загрузочные fallback сверяйте с актуальными `public/index.html`.
- Не указывайте фиксированное количество файлов/имён как бессрочную норму: при добавлении/удалении CSS обновляйте этот документ на основе фактических links и `sw.js`.
- `scripts/css-audit.mjs` проверяет ограниченный набор статических инвариантов; он не является полноценным CSS parser и не заменяет проверку computed styles.

### Общая геометрия desktop wrap и scrollbar

- `body > div.wrap` ограничен 1480px на desktop 1181–1480px; начиная с 1481px максимальная ширина повышается до 2560px и контейнер центрируется. Critical CSS первого кадра находится в `index.html` и задаёт тот же предел.
- Вертикальный scrollbar не должен менять доступную ширину layout при появлении overflow. `html { overflow-y: scroll; scrollbar-gutter: auto; }` в critical CSS постоянно выделяет место под сам scrollbar, но не создаёт дополнительный пустой gutter, который `scrollbar-gutter: stable` резервирует даже без прокрутки.

### CTA карточки доставки

- `delivery.js` владеет текстом кнопки `#deliveryGrid [data-add]`: в состоянии корзины видимо показывает `В корзине · N`, где `N` — текущее количество этой позиции. Доступное имя дополнительно объясняет действие «Добавить ещё».
- `20-cards.css` задаёт компактную типографику этого числового текста (11px) при сохранении высоты 44px. Не заменять видимый счётчик галочкой: количество должно оставаться доступным без наведения или открытия подсказки.

### Тикер объявлений

- `admin-extra.js` владеет содержимым `#tickerTrack`, измерением ширины и созданием двух одинаковых циклов из `.tickerGroup`. Число повторов рассчитывается от ширины viewport, поэтому движение продолжается и тогда, когда исходная строка короче экрана; скрытые копии исключены из accessibility tree.
- `70-ticker.css` владеет анимацией `zt-marquee`, скоростью через `--ticker-duration`, состоянием паузы и focus-visible. Клик по строке или клавиши Space/Enter переключают паузу без видимой кнопки/иконки. `prefers-reduced-motion` отключает автоматическое движение; явный пользовательский запуск разрешает его.

### AdminBar и category rail
- Мобильная геометрия `#adminBar` принадлежит `160-12-admin-bar-tail.css`; critical CSS в `index.html` только резервирует каркас первого кадра. Оба правила должны держать панель в ширине своей колонки: `width/max-width:100%`, обычный нижний margin, без компенсации ширины rail через отрицательный `margin-left`.
- Общая поверхность `#rail` / `#deliveryRail` остаётся без внешней рамки; визуальное разделение строится на брендовой заливке rail и активном индикаторе. Не добавлять обводку общей поверхности без отдельной визуальной приёмки.

### Мобильный переключатель заведения

- `core/views.js` владеет DOM-переездом `#brandSeg`, обработчиками открытия/выбора и состоянием. Мобильная геометрия и общие состояния панели принадлежат `160-04-wrap-cls-sheets.css` (Слой 1), а значения оформления по брендам — только custom properties в `brand-tokens.css` (Слой 2a). Theme/critical CSS используют эти токены, не задавая брендовые цвета напрямую.
- Панель имеет content-sized ширину с минимумом `min(180px, calc(100vw - 24px))` и максимумом `min(232px, calc(100vw - 24px))`; высота ограничена с учётом safe-area. Обе кнопки растягиваются на одинаковую ширину панели, имеют hit area не менее 44px и используют активные brand-токены. Critical CSS `index.html` и тема `160-04-wrap-cls-sheets.css` должны сохранять одинаковую геометрию первого кадра.
- Появление панели может иметь короткую transform/opacity-анимацию; `prefers-reduced-motion` отключает её. Не задавать анимацию свойству `display`.
- Critical CSS `index.html` резервирует только закрытое/открытое раннее состояние и не должен становиться вторым владельцем размеров панели.

### Текущие исключения для category rail

- DOM placement остаётся у `core/views.js`: горизонтальный rail размещается сразу после `.menu-head` внутри активного `#menuView` / `#deliveryView`; на обычном desktop rail возвращается в левую колонку `.wrap`. Отдельный host в `body` не нужен: computed ancestors у обоих rail в CI diagnostics не имеют `transform`, `filter`, `perspective`, `contain` или `will-change`, создающих fixed containing block; `overflow-x: clip` у корневых элементов не меняет containing block fixed-позиционирования.
- Геометрия горизонтального rail (`position: fixed`, `left/right/bottom: 0`, `--rail-h`, `--rail-total-h`, safe-area и z-index) принадлежит только `150-rail.css`. В portrait используется `--rail-h:56px`, в коротком landscape — `48px`; `--rail-total-h` включает safe-area ровно один раз. Устаревшая JS-модель pin сверху, spacer и класс `.rail-is-pinned` удалены. `ui/scrolltop.js` сохраняет desktop anchor/margin-top, но не задаёт мобильную геометрию; `scrollMenuContentToStart` прокручивает выбранный контент ниже нижней границы sticky topbar + 12px, не учитывая rail.
- `20-cards.css` резервирует прокрутку каталога под `--rail-total-h` и дополнительный lane только при фактически видимом `#cartFab.visible:not([hidden])`; пустая корзина не получает FAB-reserve. `160-01-rail-fab-mobile.css` располагает плавающие действия над rail. При `body.cart-open` rail и cart FAB становятся невидимыми и некликабельными; TMA MainButton остаётся владельцем нативного CTA. `index.html` (Слой 4) зеркалит только first-frame геометрию и резерв, совпадающие с theme CSS.
- Desktop sidebar по-прежнему принадлежит `160-11-canonical-grid-menu.css`; не переносить в него мобильную fixed-геометрию. Не дублировать геометрию rail в динамических CSS-правилах `views.js`.

## 3. Критерии добавления и удаления CSS

Перед добавлением правила зафиксировать:
1. Какой компонент или базовый паттерн им владеет?
2. Почему существующий слой-владелец не подходит?
3. Какие бренды и breakpoints затрагиваются?
4. Есть ли похожие правила в других слоях и являются ли они реальным дублированием или намеренным fallback/override?
5. Какой тест или скриншот подтверждает сохранение геометрии?

Не удалять повторяющиеся selectors только по совпадению текста. Учитывать media-контекст, specificity, порядок подключения, inline styles, бренд, critical fallback и hydrated DOM.

## 4. First paint, fonts и CLS

Ранний HTML/CSS должен резервировать тот же внешний размер шапки, марки, поиска, медиа карточек и фиксированных контролов, который будет после загрузки CSS/шрифтов и гидратации. Проверять:
- first paint при throttled CSS/fonts;
- геометрию после hydration;
- CLS и horizontal overflow;
- 320–390 px, промежуточные mobile widths, tablet и desktop;
- staff role hydration отдельно от guest state.

Для delivery storefront существует отдельный regression contract: `docs/testing/slow-network-layout.md`. Его порог CLS и viewport breakpoints менять только при обоснованной смене UX-контракта.

## 5. Responsive визуальная приёмка

Минимальный набор состояний:
- guest · coffee;
- guest · delivery;
- cashier;
- dispatcher;
- admin;
- cart closed/open and checkout validation;
- brand switch in both directions;
- authenticated state and cold guest state.

Снимки должны быть изолированы по роли и бренду. Не считать scrape с неизвестной сессией или скрытыми staff-панелями эталоном гостевого интерфейса.

После стилей запускайте релевантные Playwright specs и полный CI. `npm run ui:baseline` использовать только при намеренном обновлении эталона после визуального review.

## 6. Логотипы и media

- Горизонтальная марка «Пятница» использует горизонтальный SVG; квадратный raster в широком боксе запрещён, если это приводит к сжатию марки.
- Для кофейни квадратный raster + SVG fallback допустим, когда форма media-box квадратная.
- Реальную загрузку/кэширование SVG и raster сверять с актуальным `public/sw.js` и тестами.

## 7. Ownership

Полная карта DOM/CSS владельцев: `docs/module-map.md`. При переносе владения или изменении точки входа обновлять карту в том же PR. В случае расхождения сверяться с фактическим кодом и фиксировать корректировку в отдельном diff.

## 8. Проверки

- `npm run pretest`
- `npx playwright test <relevant-spec>`
- `npm run audit`
- просмотр CI screenshots/report, если сценарий их прикладывает

Не ослаблять assertions для сокрытия layout regressions. Визуальное изменение принимается только после сравнения screenshot states и review фактического responsive поведения.
