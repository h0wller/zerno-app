# [Handoff][Security] Add expiry and revocation semantics to user sessions

## Проблема

Сейчас `issueToken()` записывает токен и timestamp в таблицу `tokens`, но `authUser()` проверяет только существование токена. В проверенной реализации нет проверки возраста сессии или срока действия. При утечке bearer-токен может оставаться пригодным к использованию неопределённо долго.

Evidence:
- `server/domain/helpers.js` — `issueToken()`
- `server/middleware/auth.js` — `authUser()`
- `server/db/schema.js` — таблица `tokens`

## Предлагаемое решение

1. Зафиксировать единый серверный TTL для пользовательских сессий.
2. Проверять срок действия в общей точке аутентификации, а не дублировать проверки по роутам.
3. Добавить безопасную миграцию существующих токенов: определить политику для legacy-записей и не допустить неожиданного массового logout без согласованного решения.
4. Обеспечить отзыв текущей сессии при logout и всех сессий при удалении аккаунта/компрометации.
5. Не возвращать timestamp/секреты токенов в API и логах.

## Критерии приёмки

- Просроченный токен отклоняется одинаково всеми user-protected endpoints.
- Действующий токен продолжает работать до TTL.
- Отозванный токен перестаёт работать немедленно.
- Удаление аккаунта отзывает все пользовательские токены.
- Есть тесты на истечение, отзыв, legacy-миграцию и граничные значения времени.
- Нет зависимости от клиентских часов.

## Объём

Отдельный security PR. Не менять OTP/PIN flow и UI в этой задаче.

## Проверки

Добавить unit/integration тесты middleware и миграции; прогнать соответствующий auth test suite и CI.

## Примечание

Это handoff PR с постановкой задачи. Production-код намеренно не менялся.
