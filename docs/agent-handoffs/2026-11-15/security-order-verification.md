# Security: require verified customer state before order creation

## Зафиксированная политика

- Гость с `verified=0` не может создать заказ.
- Гость становится подтверждённым через успешный регистрационный OTP, успешный OTP-вход, подтверждённую привязку Telegram, собственный код активации или активацию сотрудником.
- Профиль, созданный сотрудником, остаётся подтверждённым по существующему контракту.
- Сотрудники с ролью `cashier`, `dispatch` или `admin` могут оформлять служебные заказы даже если их профиль не проходил гостевой OTP-flow. Доступ к этим ролям по-прежнему защищён секретом роли.
- Вход по PIN не подтверждает владение номером и не переводит pending-профиль в verified.

## Реализация

- `verifiedCustomerGuard` защищает только `POST /api/orders`: сначала требует действительную сессию, затем проверяет состояние гостя. Остальные пользовательские маршруты и история заказов не блокируются этим правилом.
- Для неподтверждённого гостя API возвращает HTTP 403 и машинный код `CUSTOMER_NOT_VERIFIED`.
- Успешный OTP-вход теперь атомарно переводит pending-профиль в verified, очищает устаревший `actcode`, записывает событие и вызывает идемпотентное начисление приветственного бонуса.
- Общий список ролей персонала используется и guard-ом, и расчётом `by_staff` в заказах.
- OpenAPI и `docs/api.md` описывают новые состояния и ответ.

## Проверки

- Pending-гость получает 403 и не создаёт строку заказа, не меняет номер заказа и не расходует промокод.
- Неверный OTP не подтверждает профиль.
- Успешный OTP-вход подтверждает профиль и позволяет оформить заказ.
- OTP-подтверждённая регистрация может оформить заказ.
- Сотрудник может активировать pending-гостя, после чего тот может заказать.
- Созданный сотрудником профиль подтверждён и может заказать после доказательства владения номером.
- Сотрудник с действующей ролью сохраняет возможность оформлять служебные заказы.

## Границы

Не переписывать весь auth flow и не требовать OTP от доверенного персонала. Гостевой `GET /api/orders/mine` остаётся доступным по обычному `userGuard`; блокируется именно создание нового заказа.
