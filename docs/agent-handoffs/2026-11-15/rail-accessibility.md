# [Handoff][A11y] Keep delivery rail aria state in sync with scroll spy

## Проблема

В delivery rail ScrollSpy переключает визуальный класс `.on` при прокрутке каталога, но не синхронизирует `aria-pressed`. Скринридер может продолжать объявлять старую кнопку выбранной, хотя визуально активна другая категория.

Evidence:
- `public/app/delivery.js` — `syncRailActiveOnScroll()`
- `public/app/delivery.js` — click/filter state handlers
- `tests/menu-header-rail-layout.spec.js` — текущие проверки состояния rail

## Предлагаемое решение

1. Разделить понятия выбранного фильтра и категории, соответствующей текущей позиции прокрутки.
2. Не использовать `aria-pressed` для состояния, которое меняется только от scroll spy, если пользователь не активировал toggle.
3. Выбрать согласованную модель: например, `aria-current` для текущей видимой секции и `aria-pressed` для реального toggle selection — либо другой семантически корректный паттерн.
4. Синхронизировать coffee и delivery rail там, где поведение действительно общее, без создания лишней абстракции.
5. Обновить тесты на мышь, touch, keyboard и scroll-driven state.

## Критерии приёмки

- Визуальное активное состояние соответствует доступному состоянию.
- Скринридер не получает ложного утверждения о выбранной toggle-кнопке.
- При ручном выборе категории и при прокрутке состояние предсказуемо.
- Не возникает двух противоречащих активных состояний.
- Проверены оба бренда и оба рейла.

## Проверки

Playwright: 390px, 820px и desktop 821px+; проверить клавиатурную навигацию и accessibility snapshot.

## Объём

Не менять дизайн рейла без необходимости. Это отдельная задача доступности поверх PR #253.
