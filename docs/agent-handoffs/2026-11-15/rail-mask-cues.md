# [Handoff][UX] Make category rail edge mask reflect actual scroll state

## Проблема

В responsive CSS для category rail задана постоянная `mask-image` с прозрачным правым краем. При этом JS уже вычисляет состояния переполнения и конца прокрутки, но CSS-маска от них не зависит. В результате край может оставаться визуально затухающим, даже если прокрутки нет или пользователь дошёл до последней категории.

Evidence:
- `public/app/core/views.js` — responsive category navigation CSS
- `public/app/menu.js` — `syncCoffeeRailCue()`
- `public/app/delivery.js` — `syncDeliveryRailCue()`
- `tests/menu-header-rail-layout.spec.js` — проверки overflow cues

## Предлагаемое решение

1. Определять реальное переполнение по `scrollWidth > clientWidth`.
2. Показывать fade/cue только на стороне, где действительно остаётся скрытый контент.
3. Убирать правый fade на конце прокрутки и левый fade в начальном положении.
4. Не маскировать текст/иконки последней кнопки; обеспечить полную видимость hit target и label.
5. Удалить старые декоративные подсказки только после того, как новая маска покрыта тестами.

## Критерии приёмки

- Нет fade, если все категории помещаются.
- При начальном положении виден только cue в сторону скрытого контента.
- В середине прокрутки cues соответствуют обоим направлениям.
- На конце прокрутки последний элемент виден полностью, без обрезки текста/иконки.
- Поведение одинаково корректно на iOS Safari и desktop Chromium.
- Проверены coffee и delivery, 390px, 820px, 821px+ и landscape.

## Проверки

Playwright screenshots до/после; assertions на границы первой/последней кнопки и computed mask. Визуально проверить в обоих брендах.

## Объём

Только визуальная логика краевых подсказок. Не возвращать старую систему декоративных стрелок и не превращать rail в дополнительные subfilters.
