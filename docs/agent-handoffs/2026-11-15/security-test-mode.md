# [Handoff][Security] Replace DB_PATH substring heuristic for order test mode

## Проблема

В `server/routes/orders.js` тестовый режим определяется не только через `NODE_ENV === 'test'`, но и через проверку, содержит ли `DB_PATH` подстроку `tmp`. Это эвристика по имени пути: production DB path с таким сегментом может случайно отключить проверки рабочего расписания и квот предзаказов.

Evidence:
- `server/routes/orders.js` — вычисление `isTestEnv` и ветви проверки расписания/предзаказов.

## Предлагаемое решение

1. Удалить проверку `DB_PATH.includes('tmp')`.
2. Использовать явный флаг, доступный только в тестовом окружении, либо строго `NODE_ENV === 'test'`.
3. Если тестовые сценарии требуют отдельного флага, валидировать его при старте и запрещать включение в production.
4. Убедиться, что тестовая конфигурация задаётся централизованно, а не через случайное имя файла.

## Критерии приёмки

- Production с DB path, содержащим `tmp`, не отключает бизнес-ограничения.
- Test environment сохраняет необходимые тестовые обходы.
- Production не может включить test mode одной переменной пути.
- Добавлены regression tests на `NODE_ENV`, разные DB_PATH и явный test flag (если он нужен).

## Объём

Не менять бизнес-правила расписания и предзаказов — только способ определения test mode.

## Примечание

Production DB_PATH не был доступен для проверки. Это подтверждённый дефект конструкции, но не доказательство срабатывания на текущем сервере. Production-код намеренно не менялся.
